# 模块库和配置写法

工作台页面由模板 `assets/workbench.html` 生成。模板里已经写好了所有模块、主题、图标、保存和导出功能。**生成工作台时只需要改模板里 `<script id="workbench-config">` 中的那段 JSON**，模板的其他部分一律不动。

## 1. 配置总览

```json
{
  "id": "wang-teacher-2026",
  "owner": "王老师",
  "title": "王老师的工作台",
  "theme": "celadon",
  "mode": "auto",
  "layout": "grid",
  "members": [],
  "projects": [],
  "focusMode": false,
  "focusMinutes": 25,
  "modules": []
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 这个工作台的唯一名字，只用英文字母、数字和连字符。数据按它保存，**修改工作台时不要改它**，否则用户之前的数据会读不到。 |
| `owner` | 否 | 用户希望被怎么称呼，显示在问候语里，如“王老师”“陈姐”。 |
| `title` | 是 | 浏览器标签页上的名字，如“王老师的工作台”。 |
| `theme` | 是 | 通用主题 `celadon` `wayfinding` `ledger` `nightdesk` `courtyard` `studio`，或行业主题 `blueprint` `vinyl` `chamber` `playroom` `depot`，见 `themes.md`。 |
| `mode` | 否 | `auto`（跟随系统，默认）、`light`、`dark`。 |
| `layout` | 是 | `single`（单栏）、`sidebar`（左侧栏 + 主区）、`grid`（主区 + 右侧辅区）。见 `design.md` 第 3 节。 |
| `members` | 否 | 家庭成员或团队成员：`[{"id": "kid", "name": "豆豆"}]`。最多 6 人，按顺序自动分配成员色。 |
| `projects` | 否 | 项目：`[{"id": "api", "name": "支付接口重构", "short": "支", "next": "补完退款的单元测试"}]`。`short` 是线路标里的一个字，`next` 是下一步（可不填）。最多 6 个。 |
| `focusMode` | 否 | `true` 时任何主题的待办都显示“专注”按钮。夜读主题默认就有，不用写。 |
| `focusMinutes` | 否 | 专注模式的分钟数，默认 25。 |
| `modules` | 是 | 模块列表，**顺序就是页面上的显示顺序**。 |

### 模块的通用字段

```json
{ "type": "today", "area": "main", "title": "今天要做的事", "items": [] }
```

- `type`：模块类型，见第 2 节。
- `area`：放在哪里。`top` 只给 `onething` 用（页面最上方通栏）；`main` 主区；`side` 辅区，平铺显示。所有模块的添加框都默认收起成末尾一行“＋ 添加……”。`single` 布局下 `side` 自动并入主区。
- `title`：模块标题，用用户的说法。不写就用默认标题。
- `items`：初始内容，用问答中得到的真实信息填。用户之后自己添加的内容会保存在浏览器里，不受配置影响。
- `id`：可不写。只有当同一种模块出现两次（比如两个随手记）时，给每个写一个不同的 `id`。

### 写 JSON 的注意事项

- 必须是合法 JSON：键名和字符串用英文双引号，最后一项后面不加逗号，不写注释。
- 日期一律写成 `YYYY-MM-DD`，时间写成 `HH:MM`（24 小时制）。待办和收支的 `time` 也可以写“上午”“晚上”这样的文字。
- 文本里不要出现 `</script>`。
- 写完后检查一遍：每个 `project`、`member` 引用的 id 都在 `projects`、`members` 里定义过。

## 2. 模块清单

每个模块：用途、什么时候推荐、配置写法。

### `today` 今天要做的事

最核心的模块，几乎每个工作台都应该有，通常放在主区第一个（有 `hero` 时排第二）。可以勾选完成、修改、删除（可撤销）、一键清除已完成。添加入口在列表末尾。定义了 `projects` 或 `members` 时，添加框里会出现对应的下拉选择。每一项可以带 `short`（两个字的简称），积木塔会用它。

```json
{ "type": "today", "area": "main", "title": "今天要做的事",
  "empty": "还没有待办。写下今天最想做完的一件事。",
  "items": [
    { "text": "批改初二（3）班的周记", "time": "16:00" },
    { "text": "修复退款金额精度问题", "project": "api" },
    { "text": "给豆豆带水彩笔", "member": "kid", "done": false }
  ] }
```

### `onething` 今天最重要的一件事

一句话，用户可以直接点击修改。画室主题下放在 `top` 区域会以超大字号显示，是该主题的标志细节。其他主题也可用，适合“事情多、容易分心”的用户。

```json
{ "type": "onething", "area": "top", "title": "今天最重要的一件事", "text": "剪完周三要发的探店视频" }
```

### `hero` 主视觉

页面的立体主角，**一个工作台最多一个**，放在主区第一个（`area: "main"`）。它把用户自己的数据变成一个可以看、可以玩的立体画面，是工作台和普通待办清单拉开差距的地方。有五种样式，和行业主题一一搭配（见 `themes.md` 第 2 节），也可以用在别的主题上：

| `style` | 画面 | 数据从哪来 | 适合 |
|---|---|---|---|
| `tower` | 等轴测小楼，一层一个阶段，可拖动旋转 | 自己的 `projects` | 有明确阶段的项目：建筑、装修、工程、产品研发、备考 |
| `vinyl` | 旋转的黑胶唱片，A 面上午，B 面下午 | 自动读取 `today` 模块的待办和时间 | 一天分上下午节奏的人：音乐人、主播、演出、培训讲师 |
| `dossier` | 一叠立体卷宗，点一份抽出来看详情和倒计时 | 自己的 `items` | 同时跟多个案件或客户：律师、咨询、财务、猎头、保险 |
| `blocks` | 积木塔，做完一件事掉下一块 | 自动读取 `today` 模块的完成情况 | 需要一点成就感的：老师、学生、宝妈、刚开始自律的人 |
| `parcels` | 三格货架，包裹按状态堆放，可增减和挪动 | 自己的 `bays` | 按状态流转的东西：电商订单、外卖、维修工单、印刷单 |

`vinyl` 和 `blocks` 依赖 `today` 模块，配置里必须同时有 `today`。

**`tower` 楼体**

```json
{ "type": "hero", "style": "tower", "area": "main",
  "projects": [
    { "name": "滨江社区图书馆", "at": 3,
      "phases": [ { "name": "概念设计", "date": "03.12" }, { "name": "方案设计", "date": "05.30" }, { "name": "扩初设计" }, { "name": "施工图", "date": "10.31" }, { "name": "施工配合" } ] }
  ] }
```

- `at`：现在进行到第几个阶段，从 0 开始数（`3` 表示前三个已完成，第四个进行中）。
- `phases` 最多 8 个，`date` 可不填，写短一点（“10.31”“12 月”）。不写 `phases` 时用建筑行业的六个默认阶段。
- 多个项目时上方出现项目切换。用户点“这个阶段完成了”会盖好一层，保存在浏览器里。

**`vinyl` 黑胶**

```json
{ "type": "hero", "style": "vinyl", "area": "main", "title": "今天这张唱片" }
```

不需要 `items`。`today` 里时间在 12:00 以后（或写着“下午”“晚上”）的进 B 面，其余进 A 面。所以生成时给待办尽量写上时间。

**`dossier` 卷宗**

```json
{ "type": "hero", "style": "dossier", "area": "main", "title": "桌上的卷宗",
  "items": [
    { "short": "合同", "title": "买卖合同纠纷", "no": "（2026）京 0105 民初 18342 号",
      "parties": "北京云帆科技有限公司 诉 华晟物流有限公司",
      "next": "朝阳法院第三法庭开庭", "date": "2026-10-13", "time": "09:30",
      "todo": [ "最后过一遍质证意见", "打印证据原件对照表" ] }
  ] }
```

- 最多 6 份，按数组顺序从下往上叠，最后一份在最上面、默认抽出。把最急的放最后。
- `short` 是卷宗标签上的两个字；`no` 是编号（案号、合同号、客户编号），可不填。
- `date` 离今天 3 天以内会自动标“紧急”，也可以写 `"urgent": true`。`flag` 是不紧急时标签上的字，默认“进行中”。
- 案号、当事人只用用户告诉你的，不要编。

**`blocks` 积木塔**

```json
{ "type": "hero", "style": "blocks", "area": "main", "title": "今天搭了 {n} 块积木" }
```

`{n}` 会换成完成的数量。积木上的字取待办的 `short`，没有就取前两个字，所以给 `today` 的每一项配一个两字的 `short`（“晨检”“午睡”）效果最好。最多叠 10 块。

**`parcels` 货架**

```json
{ "type": "hero", "style": "parcels", "area": "main", "title": "今天的包裹",
  "bays": [
    { "name": "待打包", "kind": "open", "count": 6, "hint": "先打包下午 4 点前要揽收的。",
      "orders": [ { "who": "李女士", "item": "正山小种 125g × 2", "city": "上海", "amt": "¥236" } ] },
    { "name": "待揽收", "kind": "taped", "count": 9 },
    { "name": "已发出", "kind": "sent", "count": 12 }
  ] }
```

- 固定三格，`kind` 决定包裹样子：`open` 没封口，`taped` 贴了胶带，`sent` 贴了蓝标。换成别的行业时只改 `name`（比如“待接单、制作中、已送达”）。
- `count` 是初始数量，用户之后用加减按钮和“挪一单到下一格”自己改。每格最多画 16 个箱子，数字照实显示。
- `orders` 可不填；填了会在选中那一格时列出来。

### `schedule` 这周的安排

显示接下来几天（默认 7 天）的安排，按天分组。可以写固定日期的事，也可以写每周重复的事（课表、兴趣班、例会）。

```json
{ "type": "schedule", "area": "main", "title": "这周的课和安排", "days": 7,
  "items": [
    { "text": "初二（3）班 语文", "time": "08:00", "weekday": 1 },
    { "text": "家长会", "date": "2026-10-15", "time": "19:00", "member": "me" }
  ] }
```

- `weekday`：每周重复，1 是周一，7 是周日。
- `date`：只在这一天。两者写一个。

### `projects` 进行中的项目

列出 `projects` 里的每个项目、它的下一步，以及今天待办里还有几件属于它。配合导视主题最好。只在用户同时跟进 2 个以上项目或客户时推荐。

```json
{ "type": "projects", "area": "side", "title": "进行中的项目" }
```

### `notes` 随手记

一个输入框加一串记录。可改标题和提示文字，变成“选题灵感”“想买的东西”“孩子说的趣话”等。

```json
{ "type": "notes", "area": "side", "title": "选题灵感", "placeholder": "看到好的选题先存下来",
  "items": [ { "text": "秋天的面包店合集", "at": "2026-10-10" } ] }
```

### `links` 常用网站

用户每天要打开的网站。`icon` 从 `icons.md` 的清单里选（去掉 `i-` 前缀），不写就是地球图标。

```json
{ "type": "links", "area": "side", "title": "常用网站",
  "items": [ { "name": "学校教务系统", "url": "https://example.edu.cn", "icon": "graduation-cap" } ] }
```

只放用户明确提到的网站。不知道确切网址的，不要猜，留给用户自己添加。

### `habits` 每天坚持

最近七天的打卡格子，显示连续天数。适合提到想养成习惯、想坚持做某事的用户。

```json
{ "type": "habits", "area": "side", "title": "每天坚持",
  "items": [ { "name": "豆豆读绘本 20 分钟" }, { "name": "走路 6000 步" } ] }
```

### `ledger` 这个月的收支

记一笔收入或支出，显示本月收入、支出、结余，负数红字。适合财务、店主、自由职业者、想记账的人。`amount` 收入为正、支出为负。

```json
{ "type": "ledger", "area": "main", "title": "这个月的收支", "limit": 10,
  "items": [ { "date": "2026-10-11", "text": "围巾批发进货", "amount": -3200 } ] }
```

不要编造金额。用户没提供具体收支时，`items` 留空。

### `countdown` 倒数日

离某个日子还有几天：考试、交稿、活动、生日、旅行。

```json
{ "type": "countdown", "area": "side", "title": "倒数日",
  "items": [ { "name": "期中考试", "date": "2026-11-05" } ] }
```

### `goals` 目标

一个目标拆成几步，勾完一步进度前进一格，可以随时加步骤。适合提到阶段性目标（考证、读完某本书、减重、上线某功能）的用户。拆步骤时和用户确认，不要替用户定一个他没说过的目标。

```json
{ "type": "goals", "area": "main", "title": "这个季度的目标",
  "items": [ { "name": "考过初级会计", "steps": [ { "text": "看完第一章" }, { "text": "刷完 300 道题" } ] } ] }
```

### `reading` 想看的书和课

书、课程、文章的清单，点状态按钮在“想看、在看、看完”之间切换。

```json
{ "type": "reading", "area": "main", "title": "想看的书和课",
  "items": [ { "title": "人月神话", "status": "想看" } ] }
```

### `prompts` 常用 AI 指令

把用户经常让 AI 做的事存成指令，点“复制”后粘贴到任何 AI 对话框里用。这是帮不会用 AI 的人迈出第一步的关键模块，**大多数工作台都建议放 1 到 3 条**。

```json
{ "type": "prompts", "area": "side", "title": "常用 AI 指令",
  "items": [ { "name": "写学生评语", "desc": "按学生表现写一段期末评语",
    "text": "请帮我给一名初二学生写一段 100 字左右的期末评语。学生情况：[在这里写学生的表现]。语气温和、具体，先肯定再提希望。" } ] }
```

写指令的要求：

- 根据用户在问答里说的“反复在做、很费时间”的事来写，不要写通用的“帮我写文章”。
- 指令里需要用户补充的地方用 `[方括号]` 标出，并写清楚要填什么。
- 交代清楚身份、字数、语气、格式，让用户粘贴后直接能得到可用的结果。
- `desc` 用一句话说明这条指令能做什么。

### `timer` 专注计时

一个独立的番茄钟。用户提到“容易分心”“想专注”时推荐。夜读主题的待办自带专注模式，一般不需要再放这个模块。

```json
{ "type": "timer", "area": "side", "title": "专注一会儿", "minutes": 25 }
```

## 3. 搭配建议

- 一个工作台放 **4 到 7 个模块**。少于 4 个显得空，多于 7 个用户找不到东西。
- 用了行业主题（晒图、夜场、案头、积木、货仓）时，配上对应的 `hero` 放在主区第一个；其他主题可以不放 `hero`。`examples/` 文件夹里有五个行业的完整配置，可以照着写。
- 用了 `hero` 时，同一页面不要再用 `onething` 放在顶部，两个“主角”会互相抢。
- 主区放用户每天都要操作的 1 到 3 个模块，辅区放偶尔看一眼或偶尔添加的。
- 同一类需求只放一个模块，不要待办和目标里写同样的事。
- 用户要的功能这里没有（比如“记录体重变化曲线”“和同事共享”），如实告诉用户目前做不到，用最接近的模块替代并说明差别，不要自己往模板里加代码。
